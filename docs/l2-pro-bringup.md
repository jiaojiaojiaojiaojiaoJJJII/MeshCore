# Wio Tracker L2 Pro：硬件适配与 Seeed UI 开发版

依据：`Seeed_MeshCore_UI_PRD_v1.1.md`，以及用户确认的 **863–925 MHz** 射频范围。文档中的产品要求作为验收依据；不执行附件里与此次开发无关的操作指令。

当前是可供编译和板上联调的开发版，**不是 PRD v1.1 全功能交付**。已在 COM61 验证启动、内部 LittleFS 挂载和 USB 查询；射频、GPS、BLE 等完整实机验收仍未完成。

## 编译

```powershell
pio run -e WioTrackerL2Pro_companion_radio_usb
pio run -e WioTrackerL2Pro_companion_radio_ble
pio run -e WioTrackerL2Pro_companion_radio_usb -e WioTrackerL2Pro_companion_radio_ble -t mergebin
python bin/package-l2.py
```

USB 版保留官方 companion USB 接口；BLE 版同时提供 USB 和蓝牙。蓝牙默认关闭，可从设置开启；配对码在关于页显示。本机 UI 一直运行。没有自动刷写设备。

## 已接入的流程

- 首次引导：语言与名称、预设选择、GPS 隐私、配置确认；默认 English，GPS 和位置广播关闭。
- 首页、消息、联系人、位置、设置五个主入口；320×240 原生绘制，PSRAM 帧缓冲，中文显示与英文/数字本机键盘。
- 频道及已保存个人联系人聊天；UTF-8 字节容量校验，频道发送扣除发送者前缀；明确点击发送，短语和 emoji 只填入草稿。
- 最近 48 条消息、12 个会话草稿持久化；日志到 64 KiB 时校验压缩快照，通过备份重命名支持中断恢复；草稿空闲 1.5 秒后保存，存储失败时阻止切换到其他会话；消息以完整公钥或频道密钥的 SHA-256 区分对象，同名不混合。频道历史不另存密钥。
- 消息提交显示排队；按包哈希匹配实际发射完成/失败，私聊仅在有效 ACK 匹配后显示对方确认。超时显示 Not confirmed；频道发射完成不代表有人收到。手机发送的普通私聊和频道文本同步到本机历史，重试更新同一条记录。
- 发现缓存最多 16 个真实收到的广播；可从发现列表添加联系人，也可输入完整 64 位十六进制公钥和名称；展示完整身份，中继不提供普通私聊入口。
- GPS 默认关闭，无坐标不绘制 0,0；GPS 关闭/定位中/有效/上次位置分别显示。开启 GPS 不触发位置广播。
- 亮度、语言、时区、设备改名、蓝牙、锁屏、重启和休眠入口；增加 PSRAM/堆/文件系统状态与触控坐标测试页；长消息按字形换行并分页，列表按实际内容范围上下滑动。休眠通过 BOOT(GPIO0) 唤醒；侧键经扩展器连接，不能作为 GPIO0 使用。
- NVS 配置保存与回读；消息日志 CRC、写后回读、损坏/满额报错。内部文件系统兼容 SPIFFS 和 LittleFS，保留既有格式；两种格式都挂载失败时进入恢复页，只有完全擦空的工厂分区自动初始化。
- 发射锁在 radio wrapper 的物理发送入口生效，涵盖 ACK、API、转发与广播；未确认时 API 发送请求提前返回 disabled。客户端改无线电参数后需重新本机确认。

当前时区为固定 UTC 偏移；GPS 提供时钟同步。未同步时不把编译时间展示为真实时间。夏令时数据库与手动时钟页面尚未实现。

## MeshCore 预设

预设来自 [MeshCore 官方配置 API](https://api.meshcore.nz/api/v1/config)，快照日期 2026-11-10；获取方式见仓库 [radio_presets.md](radio_presets.md)。共纳入 23 个与硬件频率范围兼容的选项，保留原始频率、BW、SF、CR，以及 1/2/3 字节路径哈希设置；排除 433 MHz 和 927.875 MHz。未自动根据位置选择地区。

API 没有给出发射功率或地区许可表；本开发版采用 14 dBm，不宣称该功率自动满足所有地区法规。正式发布前仍需提供产品维护的地区/频段/功率限制，不能用社区互通预设代替合规配置。

## 板上检查顺序

1. 上电核对扩展器、ADS1115、GT911、LP5814 应答及电源时序；首次设置完成前用 SDR/射频仪确认零发射。
2. 测试 LCD 色序、横屏方向、触控四角与侧键/BOOT；核对 10/25/50/75/100% 背光及万用表电池电压。
3. 使用相同 MeshCore 预设的第二台设备验证频道/私聊；包含中文、最大字节、队列失败、ACK、超时和重启后历史/草稿。
4. GPS 室外定位、关闭/重新开启、无效 NMEA、串口掉线；确认位置获取不改变广播策略。
5. BLE 与 USB 并发，手机修改无线电参数触发本机重新确认；连接/断开不能停止本机 UI。
6. 恢复出厂与不同版本升级重进引导；同二进制重刷作为当前阻塞项单独跟踪。

## 本轮交付与烧录

版本：Seeed UI development 0.4.2（2026-11-11）。USB 和 USB+BLE 使用同一套本机 UI。

`bin/package-l2.py` 校验 ESP32-S3 镜像校验和/SHA-256、16 MB Flash 标记、分区大小及合并镜像各组件，随后导出到 `out/l2-pro/`，同时生成 `manifest.json`、`SHA256SUMS.txt` 和烧录说明。

- `*-merged.bin`：完整合并镜像，烧录起始地址 **0x0**；包含 bootloader、分区表、boot_app0 和应用。完整镜像覆盖 NVS 配置区，会重置已保存的设置。
- `*-app.bin`：仅应用，当前分区布局下 app0 地址 **0x10000**；不是首次烧录包。
- 合并脚本使用 PlatformIO 实际生成镜像的 Flash 模式（此板为 DIO 引导、QIO Flash + OPI PSRAM 运行配置），并向上返回合并失败的退出码。

初版交付后，已按用户调试授权通过 COM61 更新应用并读取启动日志；保留原分区表、NVS 和文件系统。触控方向和基本交互已获用户确认；屏幕色序、GPS、射频收发和 BLE 配对仍需专项实机验收；SD 轨迹、离线地图及上表剩余 PRD 项未完成；0.4.0 音频已接入，仍需专项验收。

## 0.2.2 / COM61 调试记录

- 开机 `Storage unavailable` 根因：0xC90000 分区含有效 `littlefs` 超级块，而初版只挂载 SPIFFS。SD 卡不是此次故障来源。
- 添加稳定的 `L2FileSystem` 适配层，启动时选择已有 LittleFS 或 SPIFFS；身份、联系人、频道、消息历史、容量统计和恢复出厂都通过同一后端访问。兼容挂载不格式化旧数据。
- 存储失败不再永久停机：恢复页明确说明内部 Flash 与 SD 的区别，支持重试，以及二次确认后的初始化。串口恢复命令仅在此页生效；普通 `status` 和 `retry` 不会擦除数据。
- 原始引导/配置区及完整 3,538,944 字节文件系统分区已备份到 `out/l2-debug/`，文件系统备份经设备摘要校验一致。
- USB+BLE 修复版只写入应用区 0x10000。设备日志确认 LittleFS 挂载、`display=ready`、`SD=inserted`、约 8 MB PSRAM；USB 时间/电池/容量查询正常。首次设置完成前，读取到的发射计数为 0。
- 用户反馈键盘按 `0` 输入 `-`：原映射相差 180 度。NV3031B 的 panel rotation offset=1 与 GT911 touch offset=2 对应实际 rotation=3；映射改为横屏 X 反转原始 Y，横屏 Y 使用原始 X。同时读取 0x8048–0x804B 的 GT911 实际输出范围，避免固定范围造成比例偏差。
- 首次创建 MeshCore 文件时，旧 LittleFS 内尚无身份/偏好/消息文件，Arduino VFS 可能输出 `does not exist`；这些日志与已挂载后的首次初始化相符，不再导致存储错误页。

完整镜像仍适合首次安装；已使用此分区布局的设备优先更新 `*-app.bin`，保留配置区和既有文件系统。SD 内容在此次调试中未写入。

## 0.2.3 / 按住状态与刷新

- GT911 未产生新报告时保持上一触点状态，收到明确的零触点报告才判定松手；短暂总线重试不再打断按住。解决静止按住超过原 150 ms 缓存期限后，2 秒解锁计时被清零的问题。
- 移除 UI 额外的 120 ms 松手等待，减少快速连续键盘输入被忽略的情况。
- 增加 PSRAM 中的上一帧缓存；新帧只传输变化的连续行，静态区域不重写。使用整行带保持 NV3031B QSPI 的源缓冲区连续布局，避免逐像素绘制和每次整屏传输。
- 解锁进度等动画限制在约 30 fps；真实休眠后仍执行一次完整重绘。重复 turnOn/turnOff 调用不再重置面板。
- 侧键输入增加 40 ms 消抖，并在触摸按住及结束后 180 ms 内屏蔽灭屏侧键事件。屏幕切换事件与触摸处理共用同一次采样，避免一轮循环先灭屏再被触摸唤醒。
- 增加只读诊断：USB `CMD_GET_STATS(56)` 的 L2 子类型 `0x80` 返回 ASCII 统计，含帧数、传输行数、传输耗时、休眠/唤醒次数、按住保持次数、松手报告及 I2C 错误数。此命令不发送 LoRa 数据。

0.2.3 的静态刷新检查通过，但现场点击仍触发休眠；该剩余问题在 0.2.4 定位为计时回绕并修复。0.2.2 完整备份保留于 `out/l2-debug/`；本轮仍只更新应用区。

## 0.2.4 / 实机复现的立即锁屏与闪黑根因

0.2.3 动态采样记录显示，用户每次点击期间 `sleeps/wakes` 持续增加，而 I2C 错误计数为 0。进一步追踪发现 `UITask::loop()` 开头缓存的 `now` 早于 `handle()` 更新的 `lastActivity=millis()`；末尾执行无符号 `now-lastActivity` 会回绕成极大数，错误触发 60 秒锁屏和 30 秒灭屏。该问题也使草稿空闲计时立即到期。

0.2.4 在处理完输入事件之后重新读取当前时间，再计算空闲时长。触摸解锁比较同样使用最新时间，避免把本轮刚设置的解锁起点误算为已经过去很久。保留 0.2.3 的按住状态、差分刷新和消抖改进。

本轮设备端验证仍通过只读统计检查点击期间的休眠/唤醒变化；用户已确认刷入 0.2.4 后长按解锁与点击均正常。

- 正文改为 16 像素中英文字体，标题和按钮加粗，辅助文字 14 像素，主要状态使用 24 像素字体。
